# 故障排查

## 从哪里开始

1. 页面可用：顶部「诊断中心」检查环境；任务详情内「诊断此轮运行」读取该 Run 的证据。
2. daemon 无法启动：客户端「帮助 → 本机诊断（支持后台离线）」，或终端运行 `runember doctor --json`。
3. 需要分享问题：先预览诊断报告，再下载。报告包含必要的错误片段和环境信息，不包含完整日志、提示词或凭证文件；错误片段仍可能含项目路径，分享前请检查。

旧命令 `desk doctor` 仍然有效。Windows 发布包内用 `.\runember.cmd`，Mac 用 `./runember`。

客户端后台启动失败时，会先显示明确的失败原因，并提供「重试启动 / 查看诊断报告 / 退出客户端」。诊断报告由用户主动打开，关闭后返回启动恢复界面。若提示 `Cannot find package 'smol-toml'`，说明安装包缺少后台依赖，请安装修复后的完整客户端；无需重新登录 Agent，也不要删除已有任务数据。

## 常见错误

| 诊断代码 | 含义 | 建议 |
|---|---|---|
| `provider_config_missing` | Agent 没找到供应商配置 | 重新检测 CLI 路径，在对应 Agent 中完成供应商配置与登录；Agent 本身能启动时更新 Runember |
| `authentication_failed` | 模型或通知渠道认证失败 | 用后台服务的运行账号重新登录，检查具体渠道授权 |
| `executable_missing` | 执行入口或依赖未找到 | 在环境设置中选择实际的 CLI 文件 |
| `permission_denied` | 文件、目录或进程权限不足 | 检查具体出错路径及运行账号，不要批量重写项目权限 |
| `network_failed` | 连接、DNS、代理或 TLS 异常 | 先确认出错的是模型、MCP 还是通知渠道，再检查相应连接 |
| `port_conflict` / `port_in_use` | 端口被其他实例占用或数据目录不一致 | 核对运行时、端口和数据目录，确认进程归属后处理 |
| `daemon_offline` | 后台服务未响应 | 启动服务；本机诊断会尝试读取最近启动错误 |
| `timeout` | 执行时限触发 | 查看最后活动，确认连接或工具是否等待，再决定调整时限或续跑 |
| `interrupted` | 本轮结果不完整 | 保留工作区，核对最后日志后决定是否恢复原会话 |
| `executor_failed` | 执行器异常，但证据不足 | 检查原始 Run 日志；导出报告提供给维护者 |
| `configuration_invalid` | 运行配置无法读取 | 检查 JSON、环境变量和字段，不要把配置原文公开 |

诊断中的「需进一步确认」表示可能原因。诊断不会自动重试任务、修改项目文件、重置 Git 或回退外部操作。

## 查询指定任务和历史轮次

```text
runember doctor --task 20 --json
runember doctor --task 20 --run 40 --json
runember doctor --task 20 --run 40 --output task-20-run-40.json
```

CLI 从当前数据目录只读读取数据库，因此不依赖 daemon 在线。导出到已有文件会报错，避免覆盖先前报告。

## 日志在哪里

默认 `~/.agentdesk/daemon.log` 和 `~/.agentdesk/runs/*.jsonl`。更改日志目录后以环境设置中的「当前生效目录」为准。历史 Run 仍记录旧路径；不要只在新目录寻找旧日志。

Agent 自身的会话、缓存和内部日志由该 Agent 管理，Runember 日志设置不会重定向这些文件。

## 「已结束」但任务没做完

先查看结束方式、退出码及 Agent 答复。「执行器正常退出」只说明本轮运行结束。单测失败、资料不足或其他业务结果，不自动等于 Runember 执行故障。可以通过「继续」补充指令；有原会话时恢复原上下文。

## 客户端关闭，任务是否停止

关闭窗口会隐藏到托盘。退出客户端后，独立 daemon 继续运行。只有后台服务停止、执行器退出或系统休眠/关机等才会影响运行；本机无人值守执行需要电脑保持开机。
